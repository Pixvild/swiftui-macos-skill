# SwiftUI 与 AppKit 桥接

性质：作者实施指南。来源：SW17、SW18、SW19。

## 桥接方向

SW17 对应把 AppKit 的视图放进 SwiftUI，SW18 对应把 SwiftUI 的视图层级放进 AppKit。不要混淆两个方向。SW17 讨论创建、更新和清理，并警告不要直接修改由 SwiftUI 管理的视图布局属性；SW19 说明 Coordinator 的协调角色。

## 只桥接有依据的能力缺口

先定位具体需求与当前 SwiftUI API 的差距，或尊重既有 AppKit 工程的结构。单个能力不足不意味着重写整个窗口；同样，不要为了维持“全 SwiftUI”而绕开成熟的原生能力。

为包装组件定义输入状态、向外事件和生命周期。创建负责一次性配置，更新同步可变状态，清理解除订阅、回调和资源；避免每次更新都重新创建昂贵对象。Coordinator 负责必要的回调协调，不成为隐藏的全局模型。

## 防止反馈循环

模型更新原生视图、原生 delegate 回调再次更新模型可能形成循环。比较内容与身份、区分程序修改和用户编辑，并定义回写时机。不要靠无条件 DispatchQueue 延迟掩盖生命周期问题。

主线程/actor 约束取自实际声明和工程设置。不要为了静默编译诊断添加未经论证的 nonisolated 或 @unchecked Sendable。

## macOS 编辑器检查

测试 first responder、选区、标记文本、中文输入、复制粘贴、撤销重做、滚动位置、缩放、无障碍和视图销毁后回调。检查多窗口是否共享了本不该共享的 delegate 或编辑状态。

布局由明确的一方负责。对由 SwiftUI 接管的视图，先查对应尺寸协议与实际 SDK 支持，不直接硬改 frame/bounds 以“修复”所有尺寸问题。
