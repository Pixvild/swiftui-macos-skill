# 菜单、快捷键与焦点

性质：作者实施指南。来源：SW09、SW10、SW11、SW20。

## 官方锚点

SW09 描述 FocusState 随焦点变化更新，并警告重复绑定同一个焦点值可能产生歧义。SW10 描述从当前焦点及其祖先观察值。SW20 区分场景范围的值与局部焦点范围的值；SW11 给出菜单依赖当前场景和选择的相关示例。

## 命令从作用对象开始

为每条命令定义：作用对象、可用条件、快捷键、撤销行为和可发现入口。先确定“当前文档”来自哪个活动窗口，再决定菜单数据如何传递，避免任何一个全局选择变量控制所有窗口。

仅当前控件或子树获得焦点才生效的动作，与当前场景激活即可使用的动作，应采用不同范围。具体 focusedValue / focusedSceneValue 重载要单独核对，不能只搜索函数名。

## 焦点不等于选择

列表选择、文本选区、键盘焦点和活动窗口是四类状态。点击大纲、搜索、显示检查器时分别决定哪些状态改变。不要每次模型刷新都自动把焦点拉回正文；那会与用户主动切换控件冲突。

对于编辑器桥接，先确认原生视图的 first responder 与 SwiftUI 焦点绑定如何协调，再加入快捷键。使用原生撤销和文字编辑命令时，检查是否被外层自定义快捷键意外截获。

## 验收

至少测试两个文档窗口、设置窗口、正文选区、空选择、无编辑窗口、菜单打开时切换上下文、中文输入候选态以及键盘遍历。验证禁用状态与实际动作相一致，避免按钮禁用但快捷键仍操作旧文档。

只拿到截图时，不能声称命令路由、键盘可达性或输入法行为正确。输出源码位置、重现步骤和运行限制。
