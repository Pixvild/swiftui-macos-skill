# 状态、Observation 与数据流

性质：作者实施指南。来源：SW07、SW08。

## 官方锚点

SW07 的 Note 明确说明 SwiftUI 的 Observation 支持从 macOS 14 开始；其正文讨论可观察模型、状态所有权和绑定。SW08 区分本地状态、共享绑定和模型数据。此版本边界针对该集成能力，不应推广为全部 Observation 相关 API 的统一可用性。

## 先画所有权，不先替换属性包装器

对每项数据写清“唯一所有者—生命周期—读者—写入者—持久化方式”。例如正文模型属于文档，当前选中章节可能属于窗口，右栏是否打开属于 UI 状态。临时 UI 状态不能因为恰好放在模型里就被当成文档内容保存。

区分持有对象、借用对象、创建绑定与从环境读取。沿用工程现有可工作的模型，不把 ObservableObject 一概标成废弃，不因新教程出现 @Observable 就全项目迁移。

低于目标可用版本时，评估既有兼容方案、局部可用性隔离或经用户批准改变支持范围；不能直接提高部署目标。新宏或属性包装器还要核对编译器和 SDK，而不只看操作系统。

## 更新行为与并发

界面未更新时，记录实际读取了哪些属性、对象身份是否稳定、数据是否在另一处被替换；用最小可复现场景定位。不要用无意义的额外状态翻转掩盖所有权错误。

后台大纲计算、搜索和保存需要定义取消及结果回写规则：旧文档任务的迟到结果不能写入新文档。依据当前工程的隔离设置和 API 声明处理并发；不要批量加 @MainActor 或禁用诊断来跳过分析。

## 验收

检查跨视图更新、窗口间隔离、快速切换文档、取消任务、撤销、重新加载、销毁后的回调和大文本性能。写明哪些是状态模型单元测试，哪些必须在 macOS 界面上验证。
