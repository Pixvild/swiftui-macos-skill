# 文本编辑与文档生命周期

性质：作者实施指南。来源：SW12、SW13、SW14、SW15、SW16。

## 必须保留的文档差异

SW15 描述一个接收 String 绑定的纯文本初始化器；SW16 是使用 attributed strings 构建富文本编辑体验的官方样例。因此不能把某一个初始化器的限制写成“TextEditor 永远不支持富文本”。也不能因为新样例存在，就认为当前部署目标和 SDK 必定支持其所有 API。

本轮检索中，SW12 的集合页与 SW13 的具体初始化器页对弃用标记呈现不完全一致。它们可能来自不同抓取时间或页面上下文；本包不据此宣布某接口对所有目标都已弃用。实现时查具体成员、实际 SDK 及对应版本。

## 选型表先于代码

列出纯文本/Markdown/富文本、选区访问、拼写检查、查找替换、撤销分组、输入法、附件、大文档性能、导出和保存恢复的需求。逐项区分“内置支持”“需要扩展”“需要桥接”“未核验”，再比较 SwiftUI 现有接口与 AppKit。

文档场景和应用内资料库是不同架构候选。用户是否需要独立文件、多文档窗口、Finder 打开、版本恢复或统一小说项目库，应影响选择，不能仅因应用编辑文本就强制 DocumentGroup。

## 数据安全和异步任务

每次写入明确目标 URL、编码、格式版本和失败路径。不要用覆盖保存掩盖解析错误，不为“自动恢复”写空文件。遇到损坏文件、权限不足、外部修改或同步冲突，保留原始数据并给出可恢复路径。

大纲和审计计算应可取消，附带文档身份和输入版本；过期结果不得覆盖新正文。避免在持续输入期间重建文本视图导致选区、撤销栈或输入法状态丢失。

## 验收

空文件、长文、多语言、组合字符、未提交输入、快速切章、重复保存、另存、文件外部变化、异常退出后重开和同文档多窗口。量化性能时记录文档规模、设备和测试步骤；没有测量时不填造延迟数值。

SW14 的 Writing App 可用作研究样本，不等于当前产品架构已经定案，也不证明旧样例中的每个成员仍是当前推荐写法。
